DESIGN SYSTEM · DASHBOARD-BLUEPRINT

대시보드 디자인을 재사용 가능한 설계 시스템으로 바꾼 과정

참고 화면에서 설계 원칙을 추출하고, 합성 데이터와 실제 데이터로 검증해 반복 사용할 수 있는 디자인 자산으로 만드는 과정입니다.

STARTING POINT

화면을 복사하는 것만으로는 재사용할 수 없었습니다

완성된 대시보드는 차트와 색, 배치가 눈에 먼저 들어옵니다. 하지만 같은 화면을 다른 데이터에 적용하려면 이 화면이 어떤 질문에 답하는지, 어떤 비교를 우선하는지, 어떤 데이터 단위를 요구하는지까지 함께 남겨야 합니다.

dashboard-blueprint는 참고 화면을 그대로 복제하는 도구가 아닙니다. 허용된 화면·URL·HTML에서 설계 근거를 추출하고, 이를 토큰·컴포넌트·템플릿·선택 기준으로 정리한 뒤 새로운 데이터에서 다시 검증하는 시스템입니다.

결과는 템플릿 모음이 아니라, 어떤 대시보드가 왜 맞는지 설명하고 검증하는 설계 시스템입니다.

CAPTURE

보이는 요소와 설계 판단을 분리했습니다

참고 화면을 살펴볼 때 색상과 간격만 기록하지 않았습니다. 화면에서 직접 확인한 요소, 그 요소가 필요한 이유에 대한 해석, 새로운 용도에 맞게 바꾼 결정을 구분했습니다. 그래야 원본의 장점을 보존하면서도 특정 데이터나 브랜드에 종속되지 않습니다.

관찰한 요소

레이아웃, 위계, 타이포그래피, 색상, 차트와 상호작용을 근거와 함께 기록합니다.

해석한 의도

무엇을 먼저 읽게 하는지, 어떤 비교를 돕는지와 아직 확인하지 못한 부분을 구분합니다.

새로 내린 결정

새로운 데이터와 사용 목적에 맞춰 유지할 원칙과 바꿀 요소를 명시합니다.

공개 경계

재사용 권한이 확인된 자료만 다루고 원본 데이터와 브랜드 요소는 디자인 자산에 포함하지 않습니다.

REVIEW

합성 데이터로 디자인이 버티는지 먼저 확인했습니다

정상적인 예시 한 개에서 보기 좋은 화면만으로는 재사용성을 판단하기 어렵습니다. 긴 레이블, 누락된 값, 빈 상태, 극단값처럼 실제 구현에서 자주 만나는 조건을 합성 데이터로 만들고 레이아웃과 차트가 무너지지 않는지 확인했습니다.

  • 항목명이 길어져도 제목과 범례, 표의 위계가 유지되는지 확인합니다.
  • 값이 없거나 일부만 들어와도 빈 화면으로 오해하지 않게 상태를 구분합니다.
  • 큰 값과 작은 값이 함께 있을 때 비교 관계와 실제 수치를 모두 읽을 수 있게 합니다.
  • 데스크톱과 모바일, 밝은 화면과 어두운 화면에서 같은 정보가 유지되는지 살핍니다.

SELECTION

템플릿은 닮은 화면이 아니라 질문으로 고릅니다

새 데이터에 적용할 템플릿은 시각적으로 비슷한 화면을 찾는 방식으로 고르지 않습니다. 먼저 답하려는 질문과 한 행이 뜻하는 데이터 단위, 필요한 비교와 필수 필드를 확인합니다. 조건이 맞지 않으면 억지로 적용하지 않고 적합한 템플릿이 없다고 판단합니다.

01질문

사용자가 화면을 보고 결정해야 할 것은 무엇인가

02데이터 단위

한 행과 한 지표가 무엇을 뜻하는가

03비교 방식

추이·구성·상태·직접 비교 중 무엇이 필요한가

04필수 필드

해당 판단을 만들기 위해 어떤 값이 반드시 필요한가

APPROVAL

설계 승인과 공용 자산 채택을 분리했습니다

자동 검사는 파일 구조와 필수 상태, 렌더링 오류를 확인할 수 있지만 정보 위계와 비교 방식이 실제 판단에 도움이 되는지는 대신 결정할 수 없습니다. 그래서 관찰, 디자인, 실제 데이터 구현과 공용 자산 채택을 서로 다른 승인 단계로 분리했습니다.

  1. 01
    참고 자료 확인

    사용 범위와 설계 근거를 확인하고 관찰·해석·변경점을 나눕니다.

  2. 02
    합성 데이터 검토

    정상·긴 레이블·누락·빈 상태·극단값에서 디자인을 시험합니다.

  3. 03
    디자인 승인

    위계와 차트, 상호작용이 질문에 맞는지 사람이 판단합니다.

  4. 04
    실제 데이터 구현

    새 데이터의 단위와 필드를 연결하고 화면 크기별 동작을 확인합니다.

  5. 05
    실사용 검토

    값 접근성, 비교의 명확성, 예외 상태와 수정 내용을 기록합니다.

  6. 06
    공용 자산 채택

    반복 사용 가치가 확인된 구조만 내장 템플릿으로 채택합니다.

시각 기준선도 자동으로 덮어쓰지 않습니다. 화면이 달라졌다는 사실과 그 변경이 더 나은 설계라는 판단은 별개의 문제이기 때문입니다.

OUTCOME

반복 사용이 확인된 설계만 공용 자산으로 남겼습니다

합성 데이터 검토를 통과한 디자인은 실제 데이터로 한 번 더 구현하고, 브라우저에서 읽힘과 반응형 동작을 확인합니다. 같은 구조가 다른 사례에도 유효할 때 토큰, 컴포넌트, 데이터 프로필과 선택 기준을 함께 묶어 공용 자산으로 정리합니다.

선택 기준

질문, 데이터 단위, 비교 방식과 필수 필드로 템플릿 적합성을 판단합니다.

검증 절차

합성 데이터, 실제 데이터와 브라우저 검토를 연결해 화면의 완성도를 확인합니다.

재사용 자산

설계 토큰, 컴포넌트, 템플릿과 검증 기록을 함께 남겨 다음 구현에 활용합니다.

대시보드를 빠르게 한 번 만드는 것보다, 다음 데이터에서도 같은 판단 기준과 품질을 재현할 수 있는 구조를 만드는 데 초점을 맞췄습니다.
